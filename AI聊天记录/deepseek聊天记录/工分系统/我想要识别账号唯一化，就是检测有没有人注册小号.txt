这个问题问到根子上了。小号是社区经济体系的癌细胞，如果不防，你的签到送分、竞价拍卖、悬赏机制全会变成“养蛊场”。


但你没有手机号强制验证（要钱），也没有身份证实名（太敏感）。所以，我为你设计了一套“四层洋葱防御模型”，不用花一分钱，靠“前端指纹 + 后端逻辑陷阱”就能堵死99%的小号。


第一层（前端）：无感采集“浏览器指纹”（成本为0）


这是你的第一道防火墙。当用户注册或登录时，网页JS自动采集这些极难伪造的特征，合成一个device_hash（设备指纹）发给后端：


· canvas指纹（系统字体、显卡渲染差异，独一无二）
· WebGL指纹（显卡型号）
· 屏幕分辨率/色彩深度
· 已安装的字体列表（这点最准，每个人的系统字体几乎不同）
· 时区与语言（同一台电脑改IP也改不了本地时区）


后端存入数据库：如果发现新注册的账号，device_hash和老账号完全一致，直接判定为小号，立即触发风控（限制操作）。


第二层（网络）：IP段 + UserAgent 的“组合拳”


学校宿舍通常是同一个公网IP出口，不能直接封IP（否则全班同学都上不了）。


· 宽松判定：同一IP下，超过 3个账号 同时活跃，触发人工审核或签到积分减半（让你开小号性价比极低）。
· 严格判定：如果这3个账号的UserAgent（浏览器版本）完全一模一样（都是Chrome 120，且分辨率相同），视为同一台电脑虚拟机操作，直接封禁。


第三层（逻辑）：设置“新秀墙”与“成长门槛”（最狠的一招）


不要禁止注册小号，但要让小号变得“一文不值”：


1. 新手保护期限制：注册未满 7天 或 工分低于 500分 的小号，禁止参与“置顶拍卖”，禁止向其他用户转账。只能接悬赏和签到。
2. 提能门槛：要参与核心交易（发布悬赏、竞拍），必须绑定校园邮箱（edu.cn） 或完成一个真实劳动任务（比如帮别人解答一道题，获得首个好评）。批量注册的僵尸号根本过不了这关。


第四层（终极威慑）：蜜罐陷阱（钓鱼执法）


在代码里埋一个彩蛋：


· 在签到页面，故意放一个肉眼看不见的按钮（或隐藏的复选框），名为is_robot。
· 普通用户看不到，但用脚本批量注册的机器会直接点击或提交。
· 一旦后台检测到该标记被触发，反手给该IP下所有账号永久封禁，且不告知原因（让作弊者摸不着头脑）。

前端获取指纹（原生JS）：


```javascript
function getFingerprint() {
    let canvas = document.createElement('canvas');
    let ctx = canvas.getContext('2d');
    ctx.textBaseline = "top";
    ctx.font = "14px Arial";
    ctx.fillStyle = "#f60";
    ctx.fillRect(125,1,62,20);
    ctx.fillStyle = "#069";
    ctx.fillText("沙盒指纹", 2, 15);
    let fingerprint = canvas.toDataURL("image/jpeg"); 
    // 加上屏幕信息混合
    return fingerprint + '|' + screen.width + 'x' + screen.height;
}
// 注册时把 fingerprint 传给后端
```
